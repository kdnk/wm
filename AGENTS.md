# Rift fork

- Use `but` for version-control writes. Work in the existing checkout on a dedicated branch; do not create worktrees.
- When asked to land changes, use `but` to merge into local `main`. Do not create a pull request or merge through GitHub. This repository rule overrides skill workflows that require PRs. Push only when explicitly requested.
- Use `env GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=branch.main.remote GIT_CONFIG_VALUE_0= but merge BRANCH` for local-only landing. Plain `but merge` or `but land` pushes when `main` tracks a remote; the process-only override preserves the persistent tracking configuration.
- An explicit request to run `but land` authorizes its normal remote push and takes precedence over the local-only landing default above. Run `but land` without URL rewrites, remote overrides, or other changes that suppress its push. Use local-only landing only when the user explicitly requests it or asks to land changes without naming `but land`.
- The `cgs/` directory contains vendored cgs sources with the exact-capture extension required by live resizing. Preserve its license and record source updates in `cgs/README.fork.md`.
- Run `bash scripts/verify-dot-port.sh` after changing the imported Rift features. Pass a configuration file as the optional argument to validate additional app rules.
- Run `cargo +nightly fmt --all --check` after changing Rust files. Ensure the formatter is nightly; `scripts/verify-dot-port.sh` does not check formatting.
- The verification script tests LaunchAgent serialization with an isolated HOME. It must not start or stop the user's service, change signing identities, or install the daemon.
- Desktop tests under `tests/rift-*-live-test.py` require a running matching daemon and macOS permissions. Native geometry tests alone do not prove composited content rendering; retain display video and daemon traces for live resize verification.
- Use `cargo run --locked --example menu-bar-window-list-check -- --interactive` for isolated native menu interaction checks without controlling the running daemon.
- Native AppKit fixture runs must emit their expected PASS summaries. Exit status 0 without the fixture output does not establish a pass.
- After changing native window borders, run `cargo run --locked --example window-borders-check` in a macOS GUI session with Screen Recording permission. The fixture uses its own windows to check composited borders without restarting the daemon.
- For border flicker, record the affected native window and compare its composited border pixels with WindowServer stacking order during the same interaction.
- After building the `menu-bar-window-list-check` example, use `python3 tests/menu-motion-live-test.py --output NEW_DIRECTORY` to record isolated menu motion without controlling the daemon.
- Live motion tests must verify that synthetic drags commit a layout change, target fixture windows by PID and title, and restore runtime settings, workspace, and cursor position on failure.
- Before temporarily replacing a running daemon for live tests, save its layout. After restarting the original daemon, wait for its original window inventory before loading the saved layout, then verify restored window order and sizes with fresh queries.
- During layout restoration, wait until all original windows are present; allow additional windows and compare the original windows' relative order and sizes.
- `launchctl bootout` can return before launchd removes the job. Before bootstrapping a replacement plist with the same label, wait until `launchctl print gui/$(id -u)/git.kdnk.wm` reports that the service is absent.
- Unit tests must isolate mouse-state reads from the real WindowServer. Synthetic frame-change events must specify the mouse state needed by the case.
- Configuration watcher tests must use temporary paths and observe actual filesystem notifications and `ConfigUpdated` events. Do not use the user's configuration or start a daemon for these tests.
- If a configuration watcher test times out waiting for `ConfigUpdated` in a sandbox, rerun the same test with access to macOS filesystem notifications before diagnosing a regression.
- The fork's command is `wm`; use its `query`, `execute`, and `subscribe` subcommands to control the daemon. Keep Rift names in upstream attribution, archived import references, and historical verifier filenames.
- Create dependent branches with `but branch new NAME --above BASE` so their changes can reference commits on the base branch.
- Release signing uses the fixed identity prepared by `scripts/setup-release-signing.py` and pinned in `assets/release-signing.pem`. Restore the protected backup if local signing material is missing; do not generate a replacement for an established identity.
- The fixed self-signed identity has no Team ID. macOS ignores legacy `AssociatedBundleIdentifiers` for this identity. App-bundle packaging alone does not prove a background-item name change; verify the native settings UI and backgroundtaskmanagement logs before changing release or service formats.
- Run `python3 tests/release-signing-setup-test.py` after changing signing setup. Fixtures must not register live Secrets or change keychains or certificate trust.
- Run `python3 tests/release-workflow-test.py` after changing release automation. Keep tag creation and Release publication connected in one workflow; events generated with `GITHUB_TOKEN` do not start other ordinary workflows.
- Run tests, minimum Rust checks, and formatting locally with `bash scripts/verify-local.sh`. Do not add GitHub Actions test jobs for pushes, pull requests, or releases.
- Before reporting a release complete, verify the exact candidate locally and check the release workflow for the same source SHA. Report or resolve any failed, cancelled, or pending run.
- Release binaries target Apple silicon only. Preserve the legacy `wm-universal-macos-VERSION.tar.gz` asset name for existing installers.
- Run `python3 tests/install-release-test.py` after changing release installation. Keep archive/signature failures from replacing installed binaries; fixtures must not alter the real installation, service, signing material, keychains, or certificate trust.
- Stop a running service with its matching installed `wm` before replacing the binary. The CLI and daemon must agree on the checkpoint request that saves the layout before shutdown.
- `wm close-window` presses the native close button; `wm execute window close` retains Command-W behavior. Run the `sys::close_window` and wm-client tests after changing close behavior, and use `tests/close-window-live-test.py` with its PID-and-title-checked fixture for native verification.
- Run `python3 tests/motion-polish-live-test.py --focus-transition-check --output DIR` against a matching daemon after changing focus-transition hover arbitration. Verify native key-window focus during motion and hover recovery on fresh movement; logical focus alone is insufficient.
- After changing mouse-motion sampling, run `python3 tests/hover-focus-live-test.py --output NEW_DIRECTORY` against a matching daemon. The final boundary crossing must acquire native focus while the pointer remains stationary, without a later mouse event.
- After changing dialog following, run the native hover fixture with `--follow-parent` and check both IntelliJ search dialogs while scrolling. IntelliJ can report its tiled editor as an AXDialog while a picker is open. Compare both native window frames throughout the movement and after it settles.
- For picker drag tests, measure the dialog's actual offset from its editor after mouse-up. IntelliJ can move the dialog a shorter distance than the pointer. Check that scrolling away and back restores the measured offset, including after dragging at a display edge.
- IntelliJ can clamp a fully offscreen AX position back to a visible strip. Verify picker parking against the actual display edge and verify that revealing the editor restores the measured picker offset.
- Local live-test binaries must preserve the installed wm's designated signing requirement and pinned certificate. If `codesign` rejects the untrusted self-signed identity, use file-based signing without changing certificate trust; keep temporary private-key files owner-only and delete them after signing.
- If macOS denies Accessibility to a signed live-test binary at a temporary path, run the candidate at the authorized installed path. Checkpoint and stop wm with its matching client before exchanging binaries, and restore the original binary and daemon after the test.
- After changing width-command anchoring, run `python3 tests/pointer-width-live-test.py --run --output NEW_DIRECTORY --video --trace-file TRACE` against a matching daemon to verify both pointer-selected edges and arbitrary widths.
